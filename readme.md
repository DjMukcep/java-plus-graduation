# ExploreWithMe

Приложение для публикации событий, поиска мероприятий и управления участием пользователей. Проект реализован на Java с использованием Spring Boot и микросервисной архитектуры.

## Архитектура проекта

Проект состоит из трёх основных модулей: `infra`, `core` и `stats`.

- **`infra`** — инфраструктурные компоненты:
    - `gateway-server` — единая точка входа для клиентских запросов и маршрутизация запросов к микросервисам.
    - `discovery-server` — регистрация микросервисов и обнаружение их экземпляров с помощью Eureka.
    - `config-server` — централизованное предоставление конфигураций микросервисам.

- **`core`** — бизнес-логика приложения:
    - `event-service` — создание, изменение и получение мероприятий.
    - `user-service` — управление пользователями и предоставление информации о них.
    - `request-service` — управление заявками на участие в мероприятиях, изменение статусов и подсчёт заявок.
    - `comment-service` — создание, изменение, удаление и получение комментариев к мероприятиям.
    - `common` — общие DTO и централизованная обработка исключений.

- **`stats`** — компоненты системы статистики:
    - `stats-server` — сбор и предоставление статистики просмотров мероприятий.
    - `stats-client` — клиентская библиотека для взаимодействия со статистическим сервисом.
    - `stats-dto` — DTO для передачи данных статистики.

### Взаимодействие между сервисами

Для межсервисного взаимодействия используется Spring Cloud OpenFeign. Сервисы вызывают REST API друг друга через декларативные HTTP-клиенты, а Eureka позволяет находить сервисы по зарегистрированным именам.

Основные сценарии взаимодействия:

- `event-service` обращается к `user-service` для получения информации о пользователях и проверки их существования.
- `event-service` обращается к `request-service` для получения заявок, изменения их статусов и подсчёта количества заявок.
- `event-service` использует `stats-client` для отправки просмотров и получения статистики из `stats-server`.
- `comment-service` обращается к `user-service` для получения информации об авторах комментариев, проверки блокировки пользователей, обновления счётчика комментариев и выдачи предупреждений.
- `comment-service` обращается к `event-service` для проверки существования мероприятий и того, что мероприятие опубликовано, перед созданием комментария.
- `request-service` обращается к `user-service` для получения информации о пользователе при создании заявки и проверки существования пользователя при получении его заявок.
- `request-service` обращается к `event-service` для получения информации о мероприятии и проверки его состояния, инициатора и ограничения на количество участников перед созданием заявки.
- `Config Server` предоставляет конфигурации, а `Eureka Server` обеспечивает обнаружение зарегистрированных сервисов.

Для обработки сбоев межсервисных вызовов используются предусмотренные проектом механизмы отказоустойчивости, включая Resilience4j, если он настроен для соответствующих вызовов.

## Конфигурация

Конфигурация приложения задаётся в файлах `application.yml`.

- **Config Server** — централизованная конфигурация микросервисов и источник настроек, определённый в его конфигурации.
- **Eureka Server** — настройки регистрации и обнаружения сервисов.
- **Конфигурации микросервисов** — настройки портов, баз данных и межсервисного взаимодействия.
- **Gateway Server** — единая точка входа для внешних запросов, маршрутизирующая их к соответствующим микросервисам.
- **common** — общий модуль, содержащий DTO, используемые несколькими микросервисами, и централизованную обработку исключений.
- **`pom.xml`** — зависимости и настройки сборки Maven для модулей проекта.

## Внутренний API

Внутренний API используется микросервисами для взаимодействия по HTTP.

| Сервис            | Назначение внутреннего API |
|-------------------|---|
| `user-service`    | Получение информации о пользователях и проверка их существования |
| `request-service` | Получение заявок, изменение статусов и подсчёт заявок |
| `stats-server`    | Отправка просмотров и получение статистики |
| `event-service`   | Управление мероприятиями и выполнение связанных бизнес-сценариев |
| `comment-service` | Создание, получение и управление комментариями к мероприятиям |

Вызовы выполняются через REST-контроллеры и клиенты Spring Cloud OpenFeign.
